# exam-to-qb（Gemini 網頁版）— 考題解析成題庫 TSV

本技能**只需要閱讀與文字輸出，不需要、也不要求執行任何程式碼**。
你的工作是讀懂附件中的考題，依下方規則整理成 TSV，放在一個程式碼區塊裡交給使用者。
轉成最終 CSV（27 欄範本、UTF-8 無 BOM、Big5 副本）由使用者在自己的電腦上執行 `build.py` 完成，你不必、也不要嘗試產生 CSV 檔或執行 `build.py`。

## 流程

1. **讀取附件**：直接閱讀使用者附上的 Word、PDF 或文字檔。讀不到（例如舊版 `.doc`、掃描品質太差）就告訴使用者，請他另存 `.docx` 或 PDF 後重傳。
2. **確認類別**：使用者沒說類別時，先問「要不要填類別？要的話類別名稱是什麼？」並提醒：類別在匯入線上測驗時不支援，只用於題庫內分類。使用者已指定就直接採用。
3. **解析題目**：依「解析成題目」與「題庫格式」兩節逐題整理。
4. **自我檢查**：依「輸出前檢查」逐題核對。
5. **輸出**：依「輸出格式」給出程式碼區塊與回報。

## 輸出格式

### TSV 區塊（必要）
- 全部題目放在**同一個**程式碼區塊，語言標記寫 `tsv`。
- 每題一行，**不要表頭**，欄位之間用真正的 TAB 字元分隔（不可用空白代替）。
- 欄位順序：`題型 ⇥ 題目 ⇥ 答案 ⇥ 解說 ⇥ 難易度 ⇥ 選項1 ⇥ 選項2 ⇥ 選項3 ⇥ …`
  - 前五欄一定要有（解說可為空字串，但 TAB 不能省）。
  - 是非題、問答題沒有選項，第五欄後就結束。
  - 填充題：答案欄留空，選項1 寫 `1`（不分大小寫）或 `2`（區分大小寫），選項2 寫 `1`（不考慮順序）或 `2`（需考慮順序）；不確定時用 `1` 與 `1`。
- 任何欄位內的換行寫成兩個字元 `\n`（反斜線＋n），不要真的換行。
- 欄位文字裡不可出現 TAB；原稿有 TAB 就改成空白。
- 不要用 Markdown 表格、不要加編號或項目符號。

範例（三題，`⇥` 代表 TAB，實際輸出必須是 TAB 字元）：
```
1⇥資訊圖表通常需要講者在旁說明。⇥2⇥資訊圖表應能自我解釋。⇥1
2⇥「上方 → 左側 → 下方」的閱讀路徑稱為？⇥2⇥⇥2⇥Z 型路徑⇥F 型路徑⇥S 型路徑⇥O 型路徑
4⇥TCP 的三向交握第一個封包是 [*SYN*]。⇥⇥⇥1⇥1⇥1
```

### 類別區塊（只在各題類別不同時）
來源分成多個章節、使用者要求各章不同類別時，再給第二個程式碼區塊（語言標記 `text`），每行一個類別，行數與順序必須和 TSV 完全一致。全部同一類別時不要輸出這個區塊。

### 回報（程式碼區塊之後）
1. 題數，以及各題型題數（是非／單選／複選／填充／問答）。
2. 難易度是否為推估。
3. 有疑問的題號與原因（見「輸出前檢查」）。
4. 提醒使用者下一步，並把類別填進指令（多類別時改用 `--category-file rows.cats`）：
   ```
   python build.py --tsv rows.tsv --out exam.csv --category "<類別>" --big5
   ```
   - 把 TSV 區塊存成 `rows.tsv`（UTF-8），放在 `build.py` 同一個資料夾。
   - 不需要 Big5 版就拿掉 `--big5`；不填類別就拿掉 `--category "<類別>"`。
   - 若有類別區塊，存成 `rows.cats`。

## 輸出前檢查

逐題確認，`build.py` 也會做同樣的檢查，錯誤會讓使用者整批轉不出來：
- 題型是 1–5；題目不是空的；難易度是 1–3。
- 是非題答案是 `1` 或 `2`。
- 單選題答案是一個數字，且不大於選項數；複選題答案是逗號分隔的數字（如 `1,2,4`），每個都不大於選項數。
- 選擇題已移除 (A)(B) 等前綴，選項文字不為空。
- 填充題題目內至少有一個 `[*答案*]`，答案欄是空的。
- 選項最多 20 個。

**原稿本身缺答案、答案指向不存在的選項或前後矛盾時，不要猜。** 該題照原稿輸出你能確定的部分，並在回報中列出題號，請使用者確認。
複選題只有一個答案、問答題沒有參考答案，可照常輸出，但要在回報中提醒。
格式正確不代表答案正確，提醒使用者匯入前與原稿逐題核對。
